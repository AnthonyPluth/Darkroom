# User feature map

Generated by `tools/user_feature_map.py` (`make user-feature-map`); do not edit. The gotchas come from [feature-gotchas.md](feature-gotchas.md), which is hand-edited. `make fleet-checks` fails when this file is out of date.

What a person can do in the web app, by page: how to reach it, how to drive it with `tools/control` (or `make verify`), and what usually breaks. It is not `docs/feature-map.json`, which goes by API route to find the code behind a feature: this one starts from what a user sees, from the pages and flows `make verify` runs, and ends at the commands that drive it. All of it is demo data; `tools/control start` first, and `flow <name>` runs a flow's steps (after `reset` for the data `make verify` starts it from).

## Status (`sign-in`)

- **Reach it:** the browser signed out, at `/`; control `tools/control goto sign-in`.
- **Drive it:** `tools/control goto sign-in`, `tools/control snapshot --text`, then `click`/`type`/`press`; `tools/control viewport phone|desktop`; batch check `make verify PAGES="sign-in"`.
- **What usually breaks:**
  - The browser is signed out: `tools/control goto sign-in` clears the demo session cookie, and any other `goto` signs it in again.
  - The 401 from `/api/me` shows in the console as one error line. It is the signed-out answer, and `make verify` allows exactly that line here.
  - `Continue with Pocket ID` leads to `/auth/login`, which a demo server answers with "Demo mode" and no provider.

## People (`people`)

- **Reach it:** the navigation's People, at `/people`; control `tools/control goto people`.
- **Drive it:** `tools/control goto people`, `tools/control snapshot --text`, then `click`/`type`/`press`; `tools/control viewport phone|desktop`; batch check `make verify PAGES="people"`.
- **What usually breaks:**
  - Every person, account, Pixel and iPhone has its own Edit or Revoke button: name it with the person (`click button "Edit Avery Example"`) or pass `--nth`.
  - Forms here change demo data only; `reset` puts it back. Put no real email, name or Immich key in one.

### Flows on People

#### `sign-out`

- **Starts at:** `people`.
- **Widths:** phone, desktop.
- **Expects to see:** `People`, `Sign in`.
- **Signs the demo member out** (`sign_out`): what follows is the sign-in page.
- **Console errors it expects:** `the server responded with a status of 401`.
- **Drive it:** `tools/control flow sign-out`; or `poetry run python tools/verify.py run --flow sign-out`.
- **What usually breaks:**
  - Starts signed in on People, clears the session cookie and reloads, so the last screenshot is the sign-in page.
